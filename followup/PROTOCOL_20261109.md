# PER follow-up protocol v1

Status: prepared on 2026-11-09 after inspecting the original results. No new training, generation, human adjudication, or confirmatory result is claimed. This is a follow-up plan, not retrospective preregistration. The choices below are proposed operational defaults for discussion with the supervisor.

## Fixed original evidence

Retain the original Qwen2.5-1.5B-Instruct model revision, dataset revisions, preprocessing rules, original 7,600 test sources, original three rewrites, seeds 13/42/77, and saved outcomes. Do not overwrite the project, clean it in place, tune thresholds on the final examples, select the best seed, or exclude a case because it weakens the result. Human semantic judgments must remain distinct from category judgments and AI suggestions.

## Follow-up scenarios

1. **More seeds:** run five additional seeds, 101, 202, 303, 404, and 505, under the original model/order/K=3 conditions. Report these five as a follow-up cohort and the original three as the original cohort. An eight-seed description may be added with cohort labels; do not relabel the eight runs as eight independent datasets or pass mixed-configuration run records to the unmodified aggregation script.
2. **Second task order:** use AG News → DBpedia-14 → Yelp Review Full with seeds 13/42/77 and K=3. B and C mean positional stages, so the actual dataset name must accompany every endpoint. The prompt/label vocabulary follows the task, not a hard-coded B/C name.
3. **Second model family:** use HuggingFaceTB/SmolLM2-1.7B-Instruct at revision `31b70e2e869a7173562077fd711b654946d38674`, seeds 13/42/77, original task order, K=3. This model is a proposed feasible alternative rather than an outcome-selected model. The official repository lists an Apache 2.0 license and a LlamaForCausalLM architecture. The original q_proj/v_proj LoRA targets are plausible but GPU/runtime compatibility still requires a smoke check. Record the model's native chat template and keep candidate scoring and training exposure rules unchanged; differences in templates/tokenization remain a model-comparison limitation. Source: https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B-Instruct
4. **More rewrites:** use K=5 on the same 7,600 sources, retaining the original three in the same positions and adding two per source (15,200 new candidates). Use a separate imported bank and a hash-linked, author-reported human review attestation. Never replace unfavorable original candidates to improve metrics. Document generation model revisions, prompts, attempts, corrections, and review protocol. The software checks coverage and distinctness, not semantic equivalence. The old runner's import manifest describes a validation contract; it is not proof that all five were generated in one stage.

Each arm changes one factor and uses a new model/adapter run because the review archive omits the original trained adapters. The K=5 arm must wait for a completed, independently reviewed bank. Complete the original 200-pair human review first so the meaning-preservation criteria can be clarified before new-bank assessment. Do not selectively extend only the sources with favorable outcomes.

## Analysis commitments before new outcomes

Primary follow-up comparison: change in out-of-fold AUROC after the first later task (B), adding PER to the three-feature baseline (confidence, entropy, margin). This choice avoids the deterministic gold_nll transform; retain the original four-feature comparison as a labeled sensitivity analysis. Report all original fixed rankings, AP, C outcomes, transitions, recovery, PER distribution, and every seed, including one-class or empty-pool cases as undefined, not zero.

Keep five-fold training-only scaling and logistic C=1. No threshold tuning. Use the same eligible examples for each paired comparison within a run. Use 5,000 paired text-group bootstrap resamples conditional on fixed OOF predictions and report their limited scope. This existing resampling does not quantify new-training variation. Report seed-wise effects, mean and sample SD; do not turn seed rows into independent examples or call nominal intervals confirmatory significance tests. For cross-arm claims on the shared sources, design a paired source-level resampling analysis before reading new outcomes, keeping each source's predictions across seeds/models/orders together. A new implementation and statistical review are required for this cross-arm analysis; the staging script does not supply it. No pooled p-value or multiplicity-corrected significance claim is authorized by this preparation alone.

Stop on infrastructure failure and retain partial ledgers. Do not label missing inference as wrong. If an arm has no A-correct examples, preserve that result and report the prediction analysis as undefined. Do not add runs until the desired conclusion is obtained. Final run count must be fixed before execution; deviations need dated reasons.

## Run preparation

Use a Python environment with the project's training dependencies. The preparation script itself uses only the standard library and does not train or download weights.

```text
python followup_experiments.py --project "PATH_TO_ORIGINAL_Research_Project" --scenario more_seeds --destination "PATH_TO_NEW_followup_more_seeds"
python followup_experiments.py --project "PATH_TO_ORIGINAL_Research_Project" --scenario reverse_order --destination "PATH_TO_NEW_followup_reverse_order"
python followup_experiments.py --project "PATH_TO_ORIGINAL_Research_Project" --scenario second_model --destination "PATH_TO_NEW_followup_second_model"
```

For K=5, provide `--scenario more_rewrites --bank NEW_BANK.jsonl --human-bank-attestation ATTESTATION.json` and a new destination. The attestation must contain `bank_sha256`, `human_review_completed: true`, `reviewer`, `review_date`, and `protocol_version: PER-followup-20261109-v1`. A self-declared file does not authenticate review quality or independence.

Inside a prepared workspace, inspect `followup_identity.json` and `followup_config.json`. These are JSON; the original YAML loader accepts JSON syntax. Then, only with available compute and the agreed run plan, use `python run.py --config followup_config.json`, followed by `python followup_analysis.py`. No completed original runs are copied, no weights are included, and no new task outcomes are supplied in this revision package.

## Validation limits

Offline tests cover staging each scenario, unchanged copied code, refusing existing destinations, refusing absent K=5 review evidence, and synthetic K=5 schema acceptance. They do not validate language-model training, GPU memory, SmolLM2 numerical compatibility, or any new scientific result. The synthetic review declaration exists only inside a deleted temporary test directory and is never evidence of human review.

A separate generated analysis module generalizes rewrite-count checks, distribution levels and plot ticks. Original modules remain byte-identical. Analysis runtime still requires the training environment and is not validated by the staging test.
